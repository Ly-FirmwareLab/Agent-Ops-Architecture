# 为什么做这个生态

> 这一篇回答一个问题：**既然市面上已经有一堆 AI 工具，为什么还要再搭一套？**
>
> 答案不是"它们不好"，而是**它们解决的是另一个问题**。下面六个错位，是我们动手的起点。

---

## 一 · 六个正在发生的错位

### 1. AI 被困在数字世界里

大模型的输出是 token，不是动作。

它能把一份合同改到无可挑剔，却端不起一杯水；能规划一条最优路径，却没法让一辆车真的拐弯。

现在有两种"让 AI 进入物理世界"的做法 —— **把模型塞进设备**，或者**做云端 API 让设备来调**。前者算力不够、迭代跟不上；后者让设备退化成"联网开关"，网络一断就是块砖。

两者共享同一个错误假设：**智能和身体必须是同一个东西。**

### 2. 模型的能力，被入口锁死了

今天你可以在终端里让 Agent 改一个仓、跑一次分析、写一份文档。但**你人在外面、在地铁上、在开会** —— 它就停在那儿，等你想起来回到那台电脑前。

能力从来不缺，缺的是**够得着**。

现在常见的替代品是 SSH 加一个手机终端。但那只是一个黑框：看不到它在第几步、看不到它读了哪个文件、出错时也拦不住。**能连上 ≠ 能指挥。**

### 3. 算力在变便宜，"调度"没有变便宜

一个人手上可能有三台机器：一台工作站、一块树莓派、几张开发板。它们各自都能干活，但**没有一个地方能同时看见它们、指挥它们**。

算力是分散的，调度是手工的。中间那段搬运 —— 复制、粘贴、切换窗口、重新交代上下文 —— 全是人在做。

### 4. 多 Agent 是趋势，但"让 Agent 互相通信"是陷阱

两个模型互相说话，结果往往不是协同，而是**共振**：互相强化幻觉、互相推卸责任、出了问题没人认领。

更麻烦的是**可观测性**：它们之间传了什么，人看不见。一条错误的结论经过三次转述，回到你面前时已经像事实了。

### 5. 设备会联网，但不会"被指挥" —— 而且一断网就瘫痪

市面上大量 IoT 平台解决的是**采集数据、画曲线、远程开关**。它们回答的是"设备现在什么样"。

真正缺的是另一半：**谁来读这些数据、做决定、下发动作 —— 以及决定做错了，谁能拦下来。**

更少有人回答第三个问题：**主服务器挂了怎么办？** 大量"智能设备"的设计前提是"永远在线"，一旦云端不可达，用户手上就剩一块砖。

### 6. "AI 工作流"的门槛被架高了

大多数方案默认你有公网 IP、有一台常年开机的服务器、有基本的运维能力。

个人开发者和小团队卡在第一步：**光是把入口搭起来，就已经耗掉了做正事的时间。**

## 二 · 我们相信的四件事

**第一，人负责意图、决策与底线；AI 负责算力、检索与执行。**
这不是一句口号，它决定了很多具体设计：谁拥有派活权、危险动作由谁批准、出错时谁负责。

**第二，智能与躯体应当解耦。**
想事的专心想事，动手的专心动手，中间用一条窄而确定的通道连起来。
**而且这条通道断了，躯体要能自己活着** —— 连续性比智能更重要。
详见 [分布式具身智能](embodied-ai.md)。

**第三，架构比代码重要。**
代码会过时，约定不会。这套东西真正想留下的不是某一段实现，而是**一套换了技术栈仍然成立的判据** —— 见 [五条协同约定](conventions.md)。

**第四，入口必须是聊天。**
不是因为聊天更先进，而是因为**那已经是人一天里待得最久的地方**。让人为了用上 AI 而改变自己的位置，这件事本身就注定失败。

## 三 · 我们不做的事

边界比功能更能说明一套架构的立场。

| 不做 | 为什么 |
|---|---|
| **不把模型塞进每一台设备** | 算力浪费、迭代困难、断网发呆。大脑集中，躯体分布 |
| **不做"一键分发给多个 Agent"的工具** | `@` 权只归人。派给谁，永远是人做的决定 —— 再方便也不代替它 |
| **不追求 Agent 之间的自主协同** | 它们之间不能直接通信，是刻意的设计，不是缺陷。见 [全景架构 §5](architecture.md) |
| **不跟官方抢覆盖** | 官方已经有的能力，一律用官方的；我们只补它没覆盖的那一段 |
| **不在第一版里塞满功能** | 每多一个能力，就多一处能出问题的地方。宁可少，但要每个都可靠 |

---

## 四 · 这套架构想留下什么

不是又一个"AI 助手"。

而是**一份关于未来的顶层设计**：当智能开始需要一具身体、当一个人开始指挥多个 Agent 和一堆设备，
有四个问题绕不开 ——

- **躯体怎么接？**
- **断网怎么办？**
- **人站在哪？**
- **出了问题谁负责？**

我们把这四个问题摆到了台面上，并且给出了一套**已经跑得通的**答案。

用它，或者推翻它 —— 都比继续假装这些问题不存在要好。
